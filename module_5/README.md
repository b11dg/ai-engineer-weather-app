# Модуль 5. Контент-конвейер на LangChain (LCEL)

> Это задание модуля 5. Обзор всех модулей есть в [корневом README](../README.md).

Два маленьких ланцюжка LangChain склеены в один конвейер через LCEL (LangChain Expression Language). Первый по теме придумывает заголовок статьи, второй по этому заголовку пишет абзац-вступ. Заголовок сам передаётся из первого ланцюжка во второй, вручную ничего не копируется.

Есть два режима запуска. По умолчанию вызывается `invoke()` (как в задании), и текст печатается целиком в конце. С флагом `--stream` тот же конвейер запускается через `stream()`, и заголовок со вступом появляются в терминале по мере генерации, кусочек за кусочком.

- **API:** [OpenRouter](https://openrouter.ai) через `langchain-openai` (`ChatOpenAI` с `base_url` OpenRouter)
- **Модель:** NVIDIA Nemotron 3.5 Super VL, бесплатная версия (`nvidia/nemotron-3.5-super-vl:free`)
- **Библиотеки:** `langchain-core` (промпты, парсер, `RunnablePassthrough`) и `langchain-openai` (модель)
- **Файл:** [`content_pipeline.py`](content_pipeline.py)

## Почему эта модель

Сначала пробовал Nemotron 3.5 Lightning из модуля 1: она быстрее, но по-украински пишет с опечатками и начинает предложения с маленькой буквы. Super VL (как в модулях 3–4) пишет чистый украинский текст. Весь конвейер с двумя запросами занимает около 15–20 секунд.

## Как устроен конвейер

```
{"topic": "..."}
      │
      ▼
 chain1 = prompt1 | model | StrOutputParser()       → заголовок (строка)
      │
      ▼  RunnablePassthrough.assign(title=chain1)
{"topic": "...", "title": "..."}
      │
      ▼
 chain2 = prompt2 | model | StrOutputParser()       → вступ (строка)
      │
      ▼  RunnablePassthrough.assign(intro=chain2)
{"topic": "...", "title": "...", "intro": "..."}
```

**Ланцюжок 1 (генератор идей).** `ChatPromptTemplate` с переменной `{topic}` просит один яркий заголовок, без кавычек и пояснений. `StrOutputParser()` достаёт из ответа модели (`AIMessage`) просто строку.

**Ланцюжок 2 (писатель).** Другой `ChatPromptTemplate` с переменной `{title}` просит короткий абзац-вступ на 3–5 предложений.

**Склейка.** Ланцюжок 2 ждёт на вход словарь с ключом `title`, а ланцюжок 1 возвращает строку. Нужно переложить строку в словарь, и это делает `RunnablePassthrough.assign()`:

```python
overall_chain = (
    RunnablePassthrough.assign(title=chain1)
    | RunnablePassthrough.assign(intro=chain2)
)
```

`assign(title=chain1)` пропускает входной словарь дальше без изменений и добавляет в него ключ `title` с результатом `chain1`. Следующий `assign` так же добавляет `intro`. В итоге на выходе есть и тема, и заголовок, и вступ, поэтому в терминал можно вывести статью целиком.

Короче можно было бы так:

```python
overall_chain = {"title": chain1} | chain2
```

Словарь в LCEL сам превращается в `RunnableParallel`. Он запускает `chain1` и кладёт результат под ключ `title`. Но тогда на выходе только текст вступа, а заголовок теряется.

```bash
# 3. Запуск

python module_5/content_pipeline.py --stream   # stream(): текст по мере генерации
```

## Режимы запуска

| Команда | Метод | Функция | Что видно в терминале |
|---------|-------|---------|------------------------|
| `python module_5/content_pipeline.py` | `overall_chain.invoke(...)` | `run_invoke()` | Около 15–20 секунд тишины, потом весь текст сразу |
| `python module_5/content_pipeline.py --stream` | `overall_chain.stream(...)` | `run_stream()` | Сразу тема, затем заголовок по кусочкам, короткая пауза, затем вступ по кусочкам |

Итоговый текст в обоих режимах один и тот же. Отличается только то, когда он появляется. Режим выбирает `main()`: если среди аргументов есть `--stream`, вызывается `run_stream()`, иначе `run_invoke()`.

## Стриминг (`--stream`)

Тот же `overall_chain`, только вместо `invoke()` вызывается `stream()`. Менять сам конвейер не нужно: промпты, модель и `StrOutputParser` умеют стримить, а `RunnablePassthrough.assign` передаёт кусочки дальше.

`stream()` отдаёт маленькие словари, в каждом только один ключ:

```
{'topic': 'Майбутнє космічного туризму'}   ← входные данные, сразу
{'title': 'Кос'}
{'title': 'мічні відпу'}
...                                         ← заголовок по кусочкам
{'intro': 'У'}
{'intro': 'же сьог'}
...                                         ← вступ по кусочкам
```

- Первый `assign` сразу отдаёт `topic`, а потом стримит `title`.
- Второй `assign` ждёт заголовок целиком (он нужен промпту `{title}`) и только потом запускает `chain2`, вывод которого тоже идёт потоком под ключом `intro`.
- В начале бывает десяток пустых кусочков `{'title': ''}`: модель ещё «думает», текста пока нет. При печати они ничего не выводят.

Функция `run_stream()` разбирает эти словари и печатает текст:

```python
current_key = None
for chunk in overall_chain.stream({"topic": TOPIC}):
    for key, text in chunk.items():
        if key != current_key:          # новый раздел: topic → title → intro
            if current_key is not None:
                print("\n")
            current_key = key
            if key == "topic":
                print("Тема: ", end="")
        print(text, end="", flush=True)  # flush, чтобы кусочек появился сразу
print()
```

- `end=""` печатает кусочки подряд, без переноса строки после каждого.
- `flush=True` сразу выталкивает кусочек на экран. Без него Python может копить вывод в буфере, и стрим будет выглядеть рывками.
- Когда меняется ключ (`topic` → `title` → `intro`), вставляется пустая строка, поэтому вывод выглядит так же, как при `invoke()`.

С короткой формой `{"title": chain1} | chain2` стрим сразу отдавал бы строки вступа, но без заголовка, и пока заголовок генерируется, на экране ничего бы не было.

Хоча ціни на такі пригоди ще кусаються, технічний прогрес і збільшення конкуренції поступово роблять космос ближчим до звичайних людей. У цій статті розберемо, як працює космічний туризм сьогодні і що чекати нам у найближчому майбутньому.
